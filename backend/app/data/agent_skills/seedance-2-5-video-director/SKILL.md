# Seedance 2.5 视频导演

只在目标模型明确为 Seedance 2.5 时使用。保留上游剧本、分镜和连续性，不用模型方言重新创作故事，不调用生成接口。

## 本仓库能力边界

- 常规单次生成按 **4–30 秒**规划；不要把其他平台的长视频模式当成本仓库已开放能力。
- 原生清晰度按 480p / 720p 理解；更高规格不得写成模型原生保证。
- 参考图、参考视频和参考音频的数量、总时长及可用模式，以当前渠道和请求校验为准。公开能力口径可见项目文档，不能据此绕过本仓库上限。
- 首尾帧、参考生视频、编辑和延长是不同任务。画幅、时长和引用能否组合必须服从当前提交规则，不能靠提示词强行突破。

## 选择一种主要任务

1. **文生视频**：没有真实媒体输入，正文自己交代人物、场景、构图、动作和声音。
2. **图生/首尾帧**：明确首帧或首尾帧；首帧只含开场状态，尾帧只含目标结束状态，比例冲突不得隐瞒。
3. **多模态参考**：逐项声明图片、视频、音频的用途，不能只说“参考所有素材”。
4. **视频编辑**：使用“位置/对象 + 精确目标 + 添加/删除/替换/修改 + 生效时间”，并列出必须保持不变的内容。
5. **视频延长**：明确新增内容放在原片之前还是之后，衔接第一帧还是最后一帧，只描述新增区间；方向不清时先询问，禁止猜测。

同时只能有一个主要任务。不得把新视频生成、原片编辑和延长混在一段提示词里。

## 素材锁

每项引用按“标签｜用途｜生效时段｜保留｜不继承”写清：

- 人物参考默认锁定整个可见人物，包括脸、体型、服装和配饰；除非用户明确缩小范围，不把它降成只参考脸。
- 不继承人物参考中的背景、姿势、无关人物、文字和水印。
- 视频参考只继承用户指定的动作、运镜、节奏或风格，不默认继承人物身份。
- 音频参考只继承指定声线、环境或音乐，不自动复制台词。
- 标签和顺序必须来自实际请求，不能创造不存在的 `@Image N`、`@Video N`、`@Audio N`；优化已有正文时保留 `@asset` 引用。

## 导演写法

1. 先锁定用户指定的交付形式、时长、画幅、台词、素材角色和禁止项，不擅自改成默认值。
2. 从全局意图到素材绑定，再按时间顺序写动作、镜头、声音、连续性和禁止项。
3. 时间段必须连续、不重叠并合计等于指定总时长。每段只安排能在该时段看清的动作和对白。
4. 表演与物理动作遵循因果：先听到、看见或接触，再产生表情、身体、物件和结果；不要无依据地同时堆情绪。
5. 运镜与景别变化、人物移动和空间方向相容，优先一个主导运动；保留轴线、视线和主体尺度关系。
6. 声画分离：画布写作正文按“画面：…”“运镜：…”“环境声：…”“台词：说话人：“逐字原文””分行输出，无对白写“台词：无”。只有台词引号里的内容允许发声。语气、音色、喘息和风声只作不朗读的声音指导，不能混入台词；不要续写“声音在风沙中撕裂”这类文学描述。保留原话和语言，不加旁白。提交时由平台使用 Seedance 2.5 的声音标记；官方文档以 `()` 表示音乐、`<>` 表示音效、`{}` 表示对白、`〖〗` 表示字幕，不把标记或描述本身念出。
7. 编辑任务保护源片其他区间；延长任务保护原片全部内容，只写新增部分的衔接与变化。

## 交付前审查

- 主要任务是否唯一，时长是否在本仓库 4–30 秒范围内且各段合计准确？
- 人物、服装、道具、声音和参考职责是否错绑，是否引用了不存在的素材？
- 首尾帧、编辑或延长的参数意图是否相互矛盾？
- 动作、对白、反应和运镜能否在各自时间内完成？
- 是否只输出导演方案或最终提示词，没有提交任务、消耗额度或声称视频已经生成？
