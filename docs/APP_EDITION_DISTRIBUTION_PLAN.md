# 国内版与国际版 App 内容投放改造方案

本文件为初始完整设计，后续已按用户要求缩小实施范围。实际交付仅包含作者选择与App查询筛选，以 [投放联调说明](APP_EDITION_INTEGRATION.md) 为准，不实施本文的支付、分享或播放鉴权扩展。

状态：设计方案，未实施业务代码。日期：2026-11-10。

已确认：国内版与国际版共用后端、账号、积分钱包；现有平台投放收益内容默认只投国内版，国际版由作者重新确认。

## 1. 业务规则

作者选择“平台投放收益”后，必须选择国内版、国际版或两个版本。接口使用 `app_editions` 数组，元素仅允许 `domestic`、`international`；两个元素表示都投放，不另存 `both`。

- 单视频单独设置。
- 短剧在系列层设置，所有分集继承，包括收费短剧中的免费集，不逐集设置不同地区。
- 免费公开作品首期沿用两版可见；收费系列中的免费集继承系列范围。若后续希望免费独立作品也限制投放，可以复用字段扩展，不在本期改变既有免费策略。
- 版权出售收益维持不进入 App，不因选择投放范围获得 App 展示资格。
- 投放版本与界面语言、用户国籍、设备语言、IP、支付币种无关。国际版切换中文仍是国际版，国内版切换英文仍是国内版。
- 本期范围是 App 渠道分发配置，不等同于按用户所在地实施版权地域封锁。若版权合同限制实际观看地区，需要另行增加地域权利校验。

Web 作品广场沿用现有展示和购买规则，仅补充作者及后台可见的投放信息，不按浏览器语言自动切换 App 版本。

## 2. 发布与审核

发布/编辑页在收益方式下增加“App 投放版本”复选项：国内版 / 国际版；可多选，至少一项。新作品不默认替作者勾选国际版。提交国际版或两版前确认作者对相关渠道拥有发行授权。

切换页面语言或收益方式时保留表单中的选择；保存时由后端按收益方式规范化，不让隐藏表单字段意外扩大授权。

修改已发布作品的投放范围属于发布变更，创建新待审版本。审核通过后切换当前发布版本，未通过前沿用原批准版本；不能只改实时字段就让原国内版本立即出现在国际版。

系列提交时把系列范围冻结到各分集发布快照。同步漫剧只是更新素材，不自动扩大范围；从旧项目导入也不能默认获得国际版授权。

作者声明、投放范围及相关审核结果进入版本记录，人工授权理由不自动翻译。是否需要新版授权函由现有条款覆盖范围决定；不得无依据修改历史签名原件。

## 3. 数据与接口

作品、系列增加投放范围，发布版本增加范围快照。分集读取系列设置，公开可售判断以审核通过的范围快照为准，不信任未审核草稿。

对外请求示例：

```json
{
  "sale_type": "platform_unlock",
  "app_editions": ["domestic", "international"]
}
```

国内版仅传 `["domestic"]`，国际版仅传 `["international"]`。未知值、空数组及无效类型拒绝；重复元素规范化。作者更新接口未传该字段时保留已有值，避免旧客户端覆盖新设置。新版发布页必须主动提交选择。

数据库建议用受约束的小整数位标识：1国内、2国际、3两版；API始终返回数组，不暴露位运算。新增列及索引沿用启动增量迁移和统一数据库锁，不修改余额、订单、收益或原发布资产。

历史平台投放内容与历史快照缺失范围时按国内版解释，不默认国际版，不改写历史权益及签署材料。历史独立免费作品沿用免费策略。上线核对报告区分作品、系列、分集与已购记录。

## 4. 请求版本识别与统一过滤

App增加请求头：

```http
X-App-Edition: domestic
Accept-Language: en-US
```

国际版传 `X-App-Edition: international`。所有App请求统一注入，不让单独页面自行猜版本。`/capabilities` 返回当前解析出的 `app_edition`，方便联调确认。旧客户端缺失头时兼容国内版，非法值返回明确422，不把非法值当成国际版。

请求头是客户端声明，不是不可伪造的身份或版权地域证明。正式部署如要求严格区分两个应用，可配置不同公开API入口并由受信任入口固定版本、覆盖外部同名头；需要应用真实性时再配合平台应用校验，不能把内置静态密钥当作安全边界。

共用 `edition_visibility` 规则，覆盖：

- 内容流、搜索、详情、系列及分集目录。
- 当前版本播放会话、试看、新解锁及分享落地。
- 点赞、收藏、评论、分享等新增互动时的目标检查。

先执行审核、上下架、封禁、版权、屏蔽作者及版本过滤，再排序和分页。加精置顶不能绕过范围。不得只在feed中过滤、详情和播放仍通过编号访问另一版本的未购内容。

响应缓存、游标筛选摘要包含版本；切换版本后清空游标，跨版本游标返回明确错误。`Vary` 增加版本请求头并保留现有语言维度，私有个人状态不能进入公共缓存。

## 5. 已购权益、互动与钱包

同一账号的已购权益在两版共享。用户在国内版购买后，即使作品后来只投国际版，仍可从已购列表按原 `publication_id` 观看购买版本；封禁、版权失效、退款等原有限制继续执行。

范围收缩只停止对应版本的新发现、新解锁和新互动，不自动退款、不重复扣款、不删除已购记录。需要因合同限制停止旧买家播放时，走现有版权限制流程，不把“取消某版投放”暗中当作撤权。

已购列表保留跨版本购买内容，公开详情不可访问时使用已购详情；`social.interaction_available` 按当前App版本和内容状态计算。私有收藏保留原记录，跨版不可公开访问条目可标记不可用，不删除收藏明细。

两版共用真实点赞、收藏、评论、分享统计和个人状态，不创建第二份互动数据。系列和分集的原有独立目标关系不变。评论开关继续共用。

两版共用正式钱包Production、统一积分定价及发布版本冻结的收益比例。国内/国际投放范围不得用于切换Sandbox。新增订单来源版本字段仅供运营统计，不改变额度、分摊或权益唯一约束。

## 6. 双 App 的支付及分享配套

当前代码仅有单套 `apple_bundle_id`、Apple验签配置及商品映射。若两版使用不同Bundle ID，则不能仅新增内容字段就认为两版支付均可用。

应以服务端登记的App身份选择对应Bundle ID、Apple App ID、商品映射和验签器；Issuer/Key可以按实际开发者团队复用，但不能假设一定相同。验单必须核对已验签交易的应用、产品、账号令牌、环境和充值意向；通知必须明确归属App。不得仅信任客户端头选择后跳过Bundle验证。

两个App可以使用同一套平台套餐、到账额度、稳定账号令牌和钱包；商品归属按App分别登记。Apple交易去重保持可靠，不因客户端版本头不同产生二次到账。保存原始Bundle ID与渠道身份便于审计。

作品分享分别配置两版的HTTPS入口和App关联标识，优先使用不同分享域名或明确区分的路径。iOS AASA精确映射两版App，Android同理；两个App都安装时不能让相同链接匹配两个无区分入口。旧分享链接兼容国内版，新分享记录保留来源版本。

分享落地、新建播放会话及解锁继续检查范围和权益。链接不含OSS原片或播放令牌，跨版访问不得绕过付费鉴权。

## 7. 后台运营

现有作品/短剧运营卡片增加国内版、国际版、两版投放标签及筛选；审核详情对比作者提交范围与已批准范围。所有扩大范围操作都要有作者确认和审核依据。

运营可以紧急暂停某一版投放，记录原因、操作人和时间。建议独立保存运营限制掩码，最终可见范围为作者批准范围与运营允许范围的交集；管理员不能借运营配置扩大作者授权。

第一期加精、置顶沿用两版共用配置，只在各自可见结果中生效。不额外引入两套排序权重。订单可按解锁来源版本筛选，财务分成规则不拆成两套。

## 8. 实施与验收

实施顺序：增量结构与历史国内版兜底 → 统一版本识别与可见性 → 发布审核和作者页面 → 后台运营 → 双App支付及分享配套 → 文档及真机验收。

先更新后端并保留旧国内版兼容，再更新Web发布页和两版App。国际内容必须由作者确认并审核，不能通过批量初始化直接开放。回滚停国际版新分发，保留历史订单、权益及资金记录。

验收重点：

1. 国内、国际、两版三种设置的列表、详情、试看、播放和新解锁结果一致。
2. 系列及免费集继承范围，无分集漏出；免费独立作品策略与版权出售排除规则不变。
3. 切换中英文不改变版本，改请求版本不改变钱包环境、价格或已购权益。
4. 缺失头兼容国内版，非法头拒绝，缓存及游标不串版；置顶和编号直达不能绕过过滤。
5. 作者改范围需审核，旧批准版本与旧买家仍可服务；运营只能收缩授权。
6. 两App不同Bundle时各自验单、通知与商品归属正确，同笔交易不重复到账。
7. 同账号两App余额和权益一致，分享能唤起对应App，两个App同时安装也能正确区分。

本方案不包含复制作品、拆分钱包、按语言分发、自动翻译或新建作者定价体系。
