# Printfilm Studio 分镜提交空转修复

日期：2026-11-06。

## 根因

项目 430 最近一次分镜 Run `8850304d-c7f4-4532-ab5a-3f11c6e0bd64` 以 `completed` 结束，但持久事件中只有正文增量和 `done`，没有 `plan_story_shots` 工具调用、`proposal` 或画布改动。模型多次停在“现在提交分镜规划：”，运行器把没有执行必需工具的空转误记为完成。

这不是前端断线，也不是规划器在执行中崩溃。此前的 Run 没有真正进入分镜规划器，因此不会重复创建节点。

## 修复

- 故事引导将本阶段必需工具传入 Agent Run：资产阶段为 `plan_story_assets`，分镜阶段为 `plan_story_shots`。
- 系统提示明确要求必须实际输出工具 JSON，不能以“现在提交/现在创建”等过渡语收尾。
- 必需工具尚未成功时，如果模型只输出自然语言，运行器最多进行两轮纠正，告知“上一轮没有实际调用工具”并要求直接输出完整 JSON。
- 纠正轮改用完整响应，避免流式特殊标记导致工具 JSON 截断。
- 连续纠正仍不调用工具时抛出错误，Run 标记失败，不再伪装为 completed。
- 普通聊天和未指定必需工具的历史行为保持不变。

主要修改：`agent/runtime.py`、`agent/routes.py`、`agent/runs.py`。
