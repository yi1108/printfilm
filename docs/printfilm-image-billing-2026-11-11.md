# 画布图片生成零扣费修复（2026-11-11）

本地 `gpt-image-2.5` 图片任务成功后，消费记录与任务结算均为 0；此前冻结的积分全部退回。模型价目虽然标记为 token，实际使用按 `image_count` 和 `resolution` 计价的表达式。生成响应未返回用量，入账时缺少图片数量和分辨率，且 token 类型判断阻止了按张回退。

修复内容：

- 工具生成将实际使用的图片尺寸传入用量记录；每次图片交付记录一张，不依赖上游提供 token。
- 图片结算使用图片分辨率解析规则；表达式模型允许按张回退，真正的纯 token 模型保留原有逻辑。
- 表达式报价匹配规则中的分辨率大小写，避免 `2k` 未命中 `2K` 而落到 1K 价格。
- 任务预估读取任务实际选择的图片模型，避免报价沿用站点默认模型而与生成结算不一致。

验证：32 项相关测试通过，包括测试库内冻结、实际扣款、解除冻结和重复结算幂等验证。使用当前上游价目只读复算，1K 的报价与结算均为 33 积分，2K 均为 55 积分；未调用付费模型。

扩展运行计费集成测试：46 项通过、2 项既有文本计费断言失败（`test_freeze_settle_refunds_unused_estimate`、`test_billing_disabled_skips_wallet_but_settles_usage`）；将本次修改的服务模块替换为 Git HEAD 内容后独立复测，两个用例同样失败，未扩大本次图片修复范围。

历史已结算的零扣费记录未补扣；本次修改不会重置已结算任务或重复处理已有钱包流水。
